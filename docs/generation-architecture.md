# 生成速度优化：自适应成文与正文优先发布

2026-10-15。此文描述当前实现，早期审查记录见 performance-and-campus-roadmap.md。

## 用户可见行为

生成页默认选择「快速成文」，也可选择「深度精写」。

- 快速成文：12000 字符以内的字幕直接交给模型，一次返回文章 HTML 和问答卡片；更长字幕按 12000 字符分块并行提炼，再一次合成文章和卡片。整段字幕都会参与处理。
- 深度精写：保留原有 3000 字符分段摘要、大纲、5–8 章逐章生成及单独卡片请求。
- 快速模式按资料密度组织篇幅，中长视频建议约 2000–3500 字，不强制每章扩写到 800–1200 字。深度模式仍保留原扩写要求。两种模式的输出篇幅和细节保留程度不同，不能假定质量相同。
- 可以取消「补充视频截图」。开启时快速模式先显示正文，随后补充截图；深度模式为了让正文参考图注，会等待视觉上下文后再写作。
- 正文提交数据库后，任务接口就返回 article_id。前端每秒检查一次，在正文就绪时打开文章；补充任务结束后刷新同一文章。日志分别记录首次可读正文与全部完成时间。

## 依赖关系

```text
原流程：字幕 → 视觉规划/截图/图注 → 摘要 → 大纲 → 逐章生成 → 卡片 → 保存

快速路径：字幕 ┬→ 直接成文或分块提炼后成文（附带卡片）→ 保存正文 → 提前阅读
             └→ 确定性采样 → 两路并行截图 → 可用的视觉图注 ─→ 更新同一文章
```

快速模式的截图作为独立「视频关键帧」附录补充，不宣称截图内容参与了已经发布的正文推理。无视觉凭据时保留截图并注明未识别。不会把自定义文本接口误当作支持固定视觉模型的接口。

## 实现变化

1. `services/fast_writer.py` 封装自适应策略、顺序汇总、合并生成卡片与 JSON/HTML 兼容处理。纯 HTML 回退不重复请求整篇文章；无效或空响应不能发布。
2. `services/generator.py` 编排正文与可选视觉任务，先提交正文，再补充附属内容；截图、图注或深度模式卡片失败时保留已保存正文。退出时取消并等待持有的异步子任务。
3. `services/llm_service.py` 为同一个生成任务提供懒加载 HTTP 连接池。摘要和章节复用连接，各次请求单独设置 Authorization；不同生成任务拥有独立客户端。SSL 初始化放到线程，减少 Windows 上的事件循环阻塞。
4. `services/converter.py` 用 yt-dlp 获取元数据后选择一条字幕轨道，复用带 Cookie 的下载器会话读取字幕。不再下载多个语言文件或扫描共享临时目录，避免并发读取错字幕。支持 VTT/SRT、YouTube JSON3 和 Bilibili JSON，失败时最多尝试三条支持的轨道。

   兼容性修正：启用 `writesubtitles` / `writeautomaticsub` 以触发各平台提取器的字幕发现；实际调用仍为 `extract_info(download=False)`，不执行字幕文件写出。B 站提取器返回的 `data` 内嵌字幕直接读取，带 `url` 的轨道才发送下载请求。日志区分未发现轨道、已发现但读取失败及具体网络错误类型。
5. `services/stream_capture.py` 最多两路截图，保留时间顺序和黑帧重试；单次 FFmpeg 超时从 20 秒调整为 12 秒。尽可能选择接近 480p 的 HTTP 视频流。
6. `frontend/src/App.tsx` 支持正文就绪时的自动预览与最终刷新，合并轮询期间新提交的任务，防止旧快照覆盖新任务；同一轮轮询不重叠。
7. SQLite 启动检查自动添加 `generation_mode` 和 `include_visuals` 字段。已有任务标记为 deep，新任务默认 fast；原文章不需要重生成。
8. HTML→Markdown 改用 markdownify，保留表格、代码块、链接与图片，避免新生成内容在 MD 导出时失去结构。深度模式迟到或未嵌入正文的截图会补入附录，已嵌入的图片不会重复追加。

## 离线验证

在 backend 目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests/benchmark_architecture.py
```

基准固定每次模拟文本请求为 50ms，字幕提取 10ms，开启截图时模拟截图 200ms。预热后每种配置运行五次，取中位数。视觉规划也被模拟，不计入真实供应商调用；Token 值不代表真实费用。

| 9000 字符 | 关闭 | fast | 1 | 0.115s | 0.122s |
| 30000 字符 | 关闭 | deep | 17 | 0.495s | 0.568s |

## 使用与性能边界

- 重启后端并刷新前端，选择「快速成文」。追求最短完整耗时可关闭截图；需要逐章扩写选 deep。
- `GENERATION_CONCURRENCY` 仍控制单任务的摘要/章节/图注并发，默认 3，多个任务会累积。尚未引入跨任务或跨进程的供应商限流。
- 阈值按字符计算，不是精确 Token 估算；自定义小上下文模型可能需要进一步调小分块或使用其他模型。极长字幕的摘要集合仍可能超过某些模型的上下文。
- 快速路径一次生成完整文章，尚未做 Token 流式展示；正文发布后通过轮询展示，附属内容可稍后补齐。
- 视觉增强等待有 45 秒上限；取消 asyncio 等待不能强制终止已经在线程中运行的 FFmpeg/下载操作，子进程仍受自己的超时约束。
- 快速路径 JSON 若截断或格式损坏会报错，不自动重复付费生成整篇。纯 HTML 响应可保存正文，此时卡片为空。
- 日志 Tokens 仍不包含深度模式 Planner 和视觉模型的全部用量，不能作为完整账单。
- 本轮没有部署，也没有使用真实密钥跑付费模型。发布前仍应对固定视频集检查事实准确性、章节重复、卡片质量及真实 P50/P95 延迟。
